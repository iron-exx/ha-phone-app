# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note (from 02-CONTEXT.md D-11):** This is not a general design exploration. Exactly 5 controls get real UI — mute, audio routing/speaker, DTMF keypad, hold, blind transfer — plus outgoing-call target entry (CALL-03). No other screens, no polish beyond what's needed to exercise CALL-01..05. Stays test-harness-flavored, matching Phase 1's placeholder call screen (`IncomingCallActivity.kt` / `DiagnosticsView.swift`) — plain Material3 (Android) / plain SwiftUI system styling (iOS), no custom brand visual identity.

## Component Inventory (Phase 2 scope)

Two new custom screens plus one shared, reused component — nothing else gets new UI this phase.

| Component | Reused In | Platform Touchpoint |
|-----------|-----------|----------------------|
| **Dialpad** (3×4 grid: 1-9, *, 0, #, standard letter subtext) | (1) Outgoing-call target entry (CALL-03, D-12), (2) in-call DTMF (CALL-02, D-13), (3) blind-transfer target entry (CALL-04, D-14) — **one component, three call sites**, per D-13/D-14 | Android: `DialpadComposable.kt` (new) / iOS: `DialpadView.swift` (new) |
| **Outgoing Call screen** | Entry point for CALL-03 | Android: new Activity/Composable hosting `DialpadComposable` + dialed-number display + "Call" button / iOS: new SwiftUI view hosting `DialpadView` |
| **Active Call screen** | Houses the 5 CALL-01..05 controls during a live call | Android: extends `CallRegistration.kt`'s `onRegistered`/`CallControlScope` callback surface / iOS: extends `CallProvider.swift`'s `CXProviderDelegate` `didActivate`/`didDeactivate` surface |

### Active Call screen — control layout (top to bottom)

1. Call status header: remote extension + call state text ("Ringing…" / "In call 02:34")
2. Control row (3 toggle/selection controls): **Mute**, **Hold**, **Audio Routing** (routing shown as a horizontal list/segmented control of available endpoints)
3. Secondary control row (2 actions that open the shared Dialpad in an overlay/sheet): **Keypad** (DTMF), **Transfer**
4. **End Call** button (destructive-styled, full width, bottom of screen)

### Audio routing — hard constraint (from 02-RESEARCH.md)

The routing control **displays and requests changes to platform-owned state only** — it must never invent its own routing state or call `AudioManager.setCommunicationDevice()`/`startBluetoothSco()` (Android) or configure `AVAudioSession` outside CallKit's `didActivate`/`didDeactivate` (iOS) directly:
- Android: bind to `CallControlScope.availableEndpoints` (list source) / `currentCallEndpoint` (selected state) and call `requestEndpointChange()` on tap — never call `AudioManager` directly.
- iOS: bind to `AVAudioSession` route state surfaced inside `CXProvider.didActivate`; prefer `AVRoutePickerView` over a custom picker so it stays synced with Control Center automatically.

## Spacing Scale

Declared values (must be multiples of 4) — matches the 8dp/8pt grid already used in Phase 1 code (`padding(32.dp)`, `padding(16.dp)`, `Arrangement.spacedBy(16.dp)`):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4dp/pt | Dialpad key internal padding, icon-to-label gaps |
| sm | 8dp/pt | Compact spacing between dialpad letter subtext and digit |
| md | 16dp/pt | Default spacing between controls in a row, screen edge padding |
| lg | 24dp/pt | Spacing between the control row and the End Call button |
| xl | 32dp/pt | Screen-level vertical padding on Active Call / Outgoing Call screens |
| 2xl | 48dp/pt | Spacing above the call status header |
| 3xl | 64dp/pt | Not used this phase (no page-level multi-section layout) |

**Exceptions:** Dialpad keys and all 5 in-call control buttons (Mute, Hold, Audio Routing, Keypad, Transfer) must have a minimum **48dp** (Android) / **44pt** (iOS) tap target regardless of their visual/icon size — this is a platform accessibility floor, not a violation of the spacing grid; visual padding still follows the token scale above, only the effective touch target is padded further where needed to hit the minimum.

## Typography

Native mobile — sizes below apply identically as Android `sp` and iOS `pt` (both scale with the user's system text-size setting under Dynamic Type / font scale, so no separate per-platform scale is declared).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Display | 28 | semibold (600) | 1.2 |
| Heading | 20 | semibold (600) | 1.2 |
| Body | 16 | regular (400) | 1.5 |
| Label | 14 | regular (400) | 1.5 |

Usage:
- **Display (28/600):** call status header text ("In call 02:34"), dialed-number display on the Outgoing Call / Transfer sheets
- **Heading (20/600):** dialpad digit glyphs (1-9,*,0,#), screen titles ("Dial", "Transfer to")
- **Body (16/400):** all 5 control button labels (Mute, Hold, [routing endpoint name], Keypad, Transfer, End Call), the "Call" CTA label
- **Label (14/400):** dialpad letter subtext ("ABC" under 2, etc.), error/helper captions

## Color

No custom color palette this phase — platform Material3 baseline (Android) and system default accent/semantic colors (iOS), consistent with "test-harness-flavored, not a polished consumer app screen" (D-11).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Android `MaterialTheme.colorScheme.background` / iOS `Color(uiColor: .systemBackground)` | Full-screen background of the Outgoing Call screen and the Active Call screen |
| Secondary (30%) | Android `MaterialTheme.colorScheme.surfaceVariant` / iOS `Color(uiColor: .secondarySystemBackground)` | Control-tray container behind the 5 in-call buttons, dialpad key background, DTMF/transfer bottom-sheet backing |
| Accent (10%) | Android `MaterialTheme.colorScheme.primary` / iOS `Color.accentColor` (system blue) | Reserved for exactly: (1) Mute button's toggled-on state, (2) Hold button's toggled-on state, (3) the currently-selected entry in the audio-routing endpoint list, (4) the "Call" CTA on the Outgoing Call screen, (5) the "Transfer" confirm button on the transfer sheet |
| Destructive | Android `MaterialTheme.colorScheme.error` / iOS `Color.red` | Reserved for exactly: the **End Call** button. (Incoming-call Decline is native CallKit/Telecom system UI from Phase 1 — out of this contract's scope.) |

Accent reserved for: Mute (active state), Hold (active state), selected audio-routing endpoint, "Call" CTA, "Transfer" confirm button — never applied to Keypad/idle-state buttons.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | "Call" (Outgoing Call screen, initiates `makeCall` to the dialed extension) |
| Empty state heading | n/a — no list/data screens this phase |
| Empty state body | "Enter extension" — placeholder text in the dialed-number display before any digit is entered (Outgoing Call and Transfer-target screens); rendered in secondary/muted text color, not Body/primary text color |
| Error state | "Call failed. Check the extension and try again." (SIP INVITE/negotiation failure) — "Lost connection to HA-Phone. Check your network and retry." (registration/network failure, ties to CALL-05's transient-registration behavior) |
| Destructive confirmation | **End Call**: no confirmation dialog — hangup fires immediately on tap, matching standard telephony UX (no "Are you sure?" for ending a call). **Blind Transfer**: entering the target number on the shared dialpad and tapping "Transfer" IS the confirmation gesture — no secondary alert/dialog is shown. |
