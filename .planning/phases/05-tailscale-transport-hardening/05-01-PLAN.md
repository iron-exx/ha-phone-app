# Phase 5: Tailscale Transport Hardening — Plan 01

**Wave:** 1 (first plan wave)
**Goal:** Implement the Tailscale on-demand transport layer — ephemeral Tailscale connection for SIP/RTP, established when a call needs to connect, torn down when call ends. No persistent background tunnel.

## Scope

This plan covers the core Tailscale integration: key management, on-demand connection establishment, PJSIP ICE candidate integration, and the connection lifecycle (establish → use → tear down). The goal is making SIP/media connections reachable across NAT and network changes (WiFi to cellular) without manual STUN/TURN configuration.

## Plans within this Wave

### Plan 05-01: Tailscale Key Configuration in HA-Phone Dashboard
**Task 1:** Add Tailscale Auth Key field to HA-Phone Dashboard "Settings" section.
- Task 2: Field accepts Tailscale Auth Key (string input) — validated via Tailscale API `keyinfo` endpoint (optional, cached locally).
- Task 3: "Save Key" button — stores key in HA-Phone box config (encrypted, at rest); key persists across box restarts.
- Task 4: "Test Connection" button — attempts simple Tailscale status check (e.g., `tailscale status` equivalent); shows "Key valid / Key invalid / Network unreachable".
- Task 5: "Remove Key" button — clears stored key; next app launch prompts for re-entry.
- **Done when:** Admin can save a Tailscale Auth Key; test connection validates; key stored encrypted; removal prompts for re-entry on next app start.

### Plan 05-02: Tailscale Key Configuration in App Settings
**Task 1:** Add Tailscale Auth Key field to App Settings (iOS: Settings > Tailscale; Android: Settings > Tailscale).
- Task 2: Field accepts same Auth Key format as Dashboard; key entered once; synchronizes with Dashboard via backend (optional sync API) or manual match.
- Task 3: "Sign in" / "Sign out" toggle — when "signed in", app uses stored key for on-demand Tailscale connections; when "signed out", Tailscale transport disabled.
- Task 4: Key storage in iOS Keychain / Android Keystore (same pattern as Phase 3 device credentials).
- Task 5: On first launch without key: UI shows "Tailscale not configured — Transport falls back to STUN/TURN — Configure in Settings".
- **Done when:** User can enter Auth Key in App Settings; key stored securely; app reads key on launch; "not configured" state displayed when no key present.

### Plan 05-03: On-Demand Tailscale Connection Establishment
**Task 1:** After call acceptance (user taps "Answer" in CallKit/Telecom UI), trigger Tailscale connection establishment.
- Task 2: App calls Tailscale SDK/CLI ` tailscale up --accept-routes -- advertise-tags=tag -- accept-dns=false` (or equivalent SDK call) with stored Auth Key.
- Task 3: PJSIP ICE agent re-gathers candidates on the new Tailscale virtual interface (`tailscale0` on iOS/tun0 on Android).
- Task 4: SIP Offer/Answer includes new Tailscale candidate; `ice-ufrag`/`ice-pwd` include Tailscale-derived values or custom `tailscale-candidate` attribute.
- Task 5: Media flows over Tailscale encrypted tunnel; existing SIP session continues seamlessly.
- **Done when:** After call acceptance, Tailscale connection established within ~5s; PJSIP re-gathers candidates; SIP session continues over Tailscale path; Audio heard in receiver.

### Plan 05-04: Tailscale Connection Tear-Down After Call
**Task 1:** When call ends (hangup), trigger Tailscale disconnection.
- Task 2: App calls `tailscale down` (or equivalent SDK call) to tear down the Tailscale virtual interface.
- Task 3: Resources released: Tailscale IP address released; PJSIP ICE candidates on Tailscale interface removed; session torn down cleanly.
- Task 4: Optional: Brief keepalive period (≤ 5 min idle) in case of immediate redial; after 5 min, full tear-down.
- **Done when:** After hangup, Tailscale connection torn down; PJSIP reverts to previous candidate set (if fallback configured) or operates without Tailscale; battery drain from Tailscale eliminated.

### Plan 05-05: Handoff Resilience (WiFi ↔ Cellular)
**Task 1:** During active call with Tailscale, user switches from WiFi to cellular (or vice versa).
- Task 2: Tailscale automatically re-routes the virtual IP to the new network — no app intervention needed (Tailscale handles this natively).
- Task 3: PJSIP ICE re-gathers candidates on the new interface; SIP session continues without drop — `ice-receive` handles the transition.
- Task 4: User visible indicator: optional status bar icon or Diagnostics "Tailscale: connected (cellular)" vs "Tailscale: connected (WiFi)".
- Task 5: If Tailscale fails to re-route (rare, OEM-specific), fall back to previous candidate set; call quality may degrade but not drop.
- **Done when:** WiFi→cellular handoff during active Tailscale call: Tailscale re-routes automatically; PJSIP session continues; optionally shown in Diagnostics; fallback works if Tailscale fails.

## Exit Criteria

- Tailscale Auth Key enterable in both Dashboard and App; key stored securely
- After call acceptance, Tailscale connection established within ~5s
- PJSIP ICE candidates include Tailscale virtual interface IP
- Call audio heard over Tailscale path
- After hangup, Tailscale torn down; no persistent battery drain
- WiFi↔cellular handoff during active call: Tailscale re-routes automatically (or graceful fallback)
- "Not configured" state clearly displayed when no Auth Key present; fallback to STUN/TURN enabled
