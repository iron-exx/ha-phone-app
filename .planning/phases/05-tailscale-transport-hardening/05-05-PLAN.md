### Plan 05-02: Accepted Gaps Carried Forward to Future Phases (or Project Complete)
**Task 1:** Document explicitly the gaps that are accepted as still-open, following the established sign-off pattern from Phases 2, 3, and 4.
- **Task 2:** iOS Tailscale SDK Availability — "Full Tailscale iOS SDK features may be limited without Apple Developer Program; basic `tailscale up/down` CLI works, but advanced features (Keyrotation UI, Status bar integration) may be restricted. Deferred if user not enrolled."
- **Task 3:** OEM Tailscale Variability — "Some Android OEMs (Samsung, OnePlus with custom UI) may kill Tailscale background processes more aggressively; cellular Tailscale behavior may differ from Pixel; documented as known limitation, tested on Pixel only."
- **Task 4:** Cellular QoE Variability — "Tailscale over cellular may yield variable call quality depending on carrier, signal strength, and network congestion; documented as expected behavior; user advised to use WLAN for critical calls."
- **Task 5:** Attended Transfer with Tailscale Complexity — "Attended transfer with active Tailscale paths on both devices works in theory; in practice, OEM-specific Task Killer behavior may interrupt one device's Tailscale path during the transfer; documented as known limitation for Phase 5; Phase 6 may refine."
- **Task 6:** (Optional) "Full Keyrotation UI" — "Custom UI for key rotation in Settings may be beyond Phase 5 scope; simple 'Key clearing + re-prompt' flow implemented; full UI policed deferred to Project maintenance."

### Plan 05-03: Resumption Triggers (When Gaps Close)
**Task 1:** Named, concrete triggers for each carried-forward gap — not vague "someday" items.
- **Task 2:** "iOS Tailscale SDK Availability" → closes if user enrolls in Apple Developer Program ($99/yr) and tests full SDK feature set; if not, accepted as known limitation with documented workarounds.
- **Task 2:** "OEM Tailscale Variability" → closes when suitable test devices (Samsung Galaxy, OnePlus, Xiaomi) available for Tailscape behavior testing; or decision documented per OEM as "known limitation"
- **Task 3:** "Cellular QoE Variability" → accepts variable quality as expected behavior for cellular + Tailscale; user advisory documented; no further testing needed unless user complaints aggregate.
- **Task 4:** "Attended Transfer with Tailscale" → closes when attended transfer tested on target OEM devices; or documented as "known limitation: may have Task Killer interruptions; manual reconnection recommended"
- **Task 5:** "Full Keyrotation UI" → closes if custom Settings UI for key rotation desired; implemented as simple flow in Phase 5; full UI polish deferred to Project maintenance.

### Plan 05-04: Phase 5 Exit Criteria — When Is Phase 5 "Done"?
**Task 1:** Checkliste ob Phase 5 als "fertig" betrachtet werden kann:
- [ ] Tailscale Auth Key in Dashboard und App einrichtbar — Key gespeichert, Test-Verbindung funktioniert
- [ ] Nach Anrufannahme: Tailscale verbindet innerhalb von ca. 5s — ICE Candidates gesammelt, Audio über Tailscale hörbar
- [ ] nach Telefonatende: Tailscale trennt automatisch — kein Batterieverbrauch nach nachhang
- [ ] bei Netzwerk-Wechsel (WiFi↔Mobilfunk): Tailscale umleitet automatisch — SIP-Sitzung bleibt erhalten
- [ ] Tailscale unavailable → Fallback auf STUN/TURN aktiviert — user-sichtbare Info in Diagnostics
- [ ] User-facing Diagnostics: Tailscale-Karte zeigt Status; Buttons funktionieren
- [ ] Admin-Dashboard: pro-Device Tailscale-Status sichtbar; Test- und Rotate-Buttons funktionieren
- [ ] Call-Screen: Tailscale-Banner zeigt Status; Tippen öffnet Diagnostics
- [ ] Key Ablauf erkannt — UI aktualisiert; Rotation funktioniert; Fallback STUN/TURN aktiviert
- [ ] Alle sub-tasks aus Plans 05-01 bis 05-04 sind "Done" (vollständig implementiert oder als Gap marked in 05-PHASE-SIGNOFF.md)
