# Phase 4: Call-State Orchestration, Multi-Device Race & Diagnostics — Plan 03

**Wave:** 1 (third plan wave)
**Goal:** Provide users and admins with a diagnostics/status page that shows the health of push registration, SIP status, permission status, and the result of the last test push/call.

## Scope

This plan covers the user-facing diagnostics/status page in the app, and the admin-side diagnostics in the HA-Phone dashboard. The goal is transparency: users should know why calls might not be coming through, and admins should see device/SIP health at a glance.

## Plans within this Wave

### Plan 04-01 (continued): Diagnostics Status Page — User-Facing
**Task 1:** Add a "Diagnostics" or "Status" section to the app's Settings/About screen.
- Task 2: Show the following cards/blocks:
  - **Push-Dienst:** `registriert` / `nicht registriert` + letzter Test-Ergebnis (Timestamp)
  - **SIP-Konto:** `bereit` / `nicht bereit` + Extension-Nummer + Registrierungs-Timestamp
  - **Berechtigungen:** `Mikrofon: erlaubt/abgelehnt`, `Kamera: erlaubt/abgelehnt`, `Benachrichtigungen: erlaubt/abgelehnt`
  - **Systemanrufe:** `aktiviert` / `deaktiviert` (iOS: CallKit/Telecom registriert; Android: ConnectionService registriert)
  - **Letzter Test-Push:** `erfolgreich um HH:MM` / `fehlgeschlagen um HH:MM` + Button "Test-Push neu senden"
  - **Letzter eingehender Anruf:** `14:32 Uhr` / `keine Anrufe verpasst` + Timestamp
- Task 3: Each card has a "Testen" Button that triggers the respective test (Test-Push, SIP-Register-Check, Permission-Check).
- Task 4: Error states shown with specific Toasts: "Push nicht registriert — Gehe zu Einstellungen" / "SIP nicht registriert — Prüfe HA-Phone Box / Neustart App"
- **Done when:** User kann auf "Testen" drücken und sieht Live-Status aktualisieren; alle Felder werden aus App-State und HA-Phone Backend gezogen.

### Plan 05-02: Admin Diagnostics — HA-Phone Dashboard
**Task 1:** Add a "Geräte- und Call-Status" Seite im HA-Phone Dashboard (für Admins).
- Task 2: Liste aller Devices pro Extension mit Status-Indikatoren:
  - `Push-Status`: `ok` / `fail` / `unknown` (letzter Heartbeat-Timestamp)
  - `SIP-Status`: `registered` / `unregistered` / `registering` (bei Registrierung vergangene Zeit)
  - `Zertifikat`: `gültig` / `abläuft in X Tagen` / `abgelaufen`
  - `Letzter Anruf`: `HH:MM vor X Min` / `keine Anrufe`
- Task 3: Buttons für Aktionen: "Test-Push senden", "SIP-Status neu prüfen", "Gerät neuprovisionieren"
- Task 4: Logs-section: "Letzte 10 Events" mit Timestamp, Event-Type, Outcome, Admin-Notizen
- **Done when:** Admin sieht alle Device-Status auf einen Blick; Buttons triggern API-Calls und zeigen Ergebnis an.

### Plan 06-03: Push-Registrierungs-Check (App-seitig)
**Task 1:** App prüft bei Start ob Push-Token gültig ist (iOS: `PKPushRegistry` Status; Android: `FirebaseInstanceId` valid).
- Task 2: Wenn Token invalid → zeige in Diagnostics "Push nicht registriert" mit Button "Neu registrieren" → öffne System-Einstellungen für Push-Berechtigungen.
- Task 3: Wenn Token valid → zeige "Push registriert" + Timestamp letzten erfolgreichen Tests.
- **Done when:** App kann Push-Status selbst prüfen und User zur Fehlerbehebung leiten.

### Plan 07-04: SIP-Register-Check (App-seitig)
**Task 1:** App prüft SIP-Registrierungsstatus via PJSUA2/JNI — ist das Konto aktuell bei Asterisk registriert?
- Task 2: Wenn nicht registriert → zeige "SIP nicht registriert" mit Button "Registrierung neustarten" → triggert `SIP-Register` neu (transient registration per CALL-05).
- Task 3: Wenn registriert → zeige "SIP registriert seit HH:MM" + IP-Adresse des Asterisk-Servers (aus Config).
- **Done when:** App kann SIP-Status selbst prüfen und User zur Fehlerbehebung leiten.

### Plan 08-05: Letzter Test-Push / Letzter Anruf History
**Task 1:** Speichern von History-Einträgen lokal (UserDefaults/iCloud sync-fähig oder SQLite) mit: Timestamp, Event-Type (test-push/incoming-call), Outcome (success/failed), Call-ID (falls vorhanden), Admin-Name.
- Task 2: In Diagnostics anzeigen: "Letzter Test-Push: erfolgreich um 14:32" / "Letzter Anruf: vermisst um 10:15" — mit Button "Details anzeigen".
- Task 3: Limitierte History (letzte 5 Einträge), ältere werden überschrieben.
- **Done when:** History wird lokal gespeichert; In Diagnostics anzeigbar; Button zeigt Details (Call-ID, Dauer, etc.).

## Exit Criteria

- User-facing Diagnostics Seite zeigt alle required Fields (Push, SIP, Permissions, Calls) mit aktuellen Status
- "Testen" Buttons funktionieren und aktualisieren Status
- Admin-facing Dashboard zeigt Device-Status pro Extension mit Push/SIP/Zertifikat-Info
- History-Einträge werden gespeichert und können angezeigt werden
- User kann durch Drücken von "Testen" Probleme diagnostizieren und beheben (z.B. Push-Neuregistrierung öffnet Settings)
