# Phase 3: QR Provisioning & Device Management — Plan 01

**Wave:** 1 (first wave of Phase 3)
**Goal:** Prove that a new device can be fully provisioned by scanning a QR code — from App start through SIP credential setup and Push-Token registration — without any manual SIP data entry.

## Scope

This plan covers the end-to-end QR provisioning flow for a single device. The admin creates a provisioning token, the user scans the QR code, and the app completes setup automatically.

## Plans within this Wave

### Plan 01-01: QR-Code Generation Endpoint (Backend)
**Task 1:** Implement `POST /api/mobile/provision/start` in HA-Phone FastAPI backend.
- Generate Ed25519 JWT (signed with developer account key)
- Claims: `{ sub: extension_id, purpose: "provision", exp: timestamp + 5min, iat: now, jti: random, app_platform }`
- Return: `{ pbx_url, sip_domain, extension, transport: "tls", media_encryption: "srtp", stun_servers, turn_servers, codecs: ["opus", "g722", "g711_ulaw", "g711_alaw"], display_name, internal_number, config_version, expires_at, cert_bundle_pem, cert_expires_at }`
- **Done when:** Endpoint returns valid JWT + config; JWT verified by app on scan

### Plan 01-02: QR-Code Scanner & Token Validation (iOS)
**Task 1:** Implement QR-Scanner screen in Swift/SwiftUI.
- Camera preview with overlay frame
- After scan: decode `haphone://provision?t=<JWT>` or Universal Link `https://pbx.example.de/app/setup?t=<JWT>`
- Validate JWT signature against hardcoded developer public key (or fetch from keychain)
- Reject expired tokens (exp claim < now)
- Reject already-used tokens (server-side invalidation)
- **Done when:** Scanner reads QR, validates JWT, shows "Config valid" or "QR abgelaufen/ungültig" Toast

### Plan 01-03: QR-Code Scanner & Token Validation (Android)
**Task 1:** Implement QR-Scanner screen in Kotlin/Jetpack Compose.
- Camera preview with overlay frame (use Android ML Kit or custom CameraX implementation)
- After scan: decode URI, extract JWT, validate signature
- Same validation logic as iOS (exp, jti, purpose)
- **Done when:** Scanner reads QR, validates JWT, shows appropriate Toast ("QR gültig", "QR abgelaufen", "QR schon benutzt")

### Plan 01-04: Cross-Platform Config Parsing
**Task 1:** Parse the full config from `/provision/start` response into shared Data Models.
- iOS: Swift structs decoded from JWT payload + HTTP response JSON
- Android: Kotlin data classes decoded from JWT payload + HTTP response JSON
- Both from same OpenAPI-generated client (retrofit/Moshi for Kotlin, URLSession/decodable for Swift)
- **Done when:** Both platforms can extract: pbx_url, sip_domain, extension, transport, codecs, cert_bundle_pem, and present them in a "Ready to complete" screen

### Plan 01-05: Push-Token Registration Flow (iOS)
**Task 1:** After QR scan + config load, register APNs Push-Token with HA-Phone Relay.
- App presents system Push-Token picker (or uses existing registered token)
- Send `{ push_token, device_id: os_id, app_platform: "ios" }` to `POST /api/mobile/provision/complete`
- HA-Phone validates token binds device → platform → extension
- Response: `{ success: true, device_cert_fingerprint }`
- **Done when:** App can register Push-Token and receive success response from HA-Phone backend

### Plan 01-06: Push-Token Registration Flow (Android)
**Task 1:** After QR scan + config load, register FCM Push-Token with HA-Phone Relay.
- FCM data-only high-priority message receipt via `FirebaseMessagingService.onMessageReceived()`
- Send `{ push_token, device_id: os_id, app_platform: "android" }` to `POST /api/mobile/provision/complete`
- HA-Phone validates and stores binding
- Response: `{ success: true, device_cert_fingerprint }`
- **Done when:** App can register Push-Token and receive success response from HA-Phone backend

### Plan 01-07: Success Screen & Completion Marker
**Task 1:** After `/provision/complete` success, show "Eingerichtet als [Extension] [Gerätename]" screen.
- Display: Extension number, Device name, "Testanruf starten" Button
- Mark device as "provisioned" in local storage/Keychain
- Enable outgoing call UI (dialpad) for this device
- **Done when:** User sees success screen, can tap "Testanruf starten" and initiate SIP connection to HA-Phone test extension

## Exit Criteria

- Admin can open "Mobilgerät hinzufügen" in HA-Phone Dashboard → QR-Code appears → User scans QR with either iOS or Android app
- App completes provisioning: Config loaded → Push-Token registered → Device marked provisioned
- Success screen displayed with "Testanruf starten" option
- No manual SIP server/port/username/password entry required at any point
- Both iOS and Android implementations work identically (same API contracts, same QR format)
