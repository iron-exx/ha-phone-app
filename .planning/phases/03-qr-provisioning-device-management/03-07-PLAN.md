**Task 1:** Named, concrete triggers for each carried-forward gap — not vague "someday" items.
- **Task 2:** "iOS Real-Device Push Verification" → closes when user enrolls in Apple Developer Program ($99/yr)

### Plan 07-04: Phase 3 Exit Criteria — When Is Phase 3 "Done"?
**Task 1:** Checkliste ob Phase 3 als "fertig" betrachtet werden kann:
- [ ] QR-Scanner auf iOS und Android funktioniert end-to-end (Scan → Config → Push-Register → Success)
- [ ] Outgoing Call UI ist nach Provisionierung sofort verfügbar
- [ ] Device-Status überlebt App-Neustart (sofern Token noch gültig)
- [ ] Admin kann alle Device-Aktionen aus Dashboard durchführen (Sperren, Löschen, QR regenerieren, Zert erneuern, Test-Push)
- [ ] Alle Edge Cases (abgelaufen, ungültig, Netzwerk) werden gefangen und zeigen user-friendly Meldungen
- [ ] Kein Absturz bei Fehler-Szenarien
- [ ] Offline-Queue funktioniert bei App-Neustart nach Netzwerk-Return
- [ ] Alle sub-tasks aus Plans 03-01 bis 03-06 sind "Done" (vollständig implementiert oder als Gap marked)

**Task 2:** Wenn alle Exit Criteria TRUE → Phase 3 sign-off schreiben in `03-PHASE-SIGNOFF.md` und Phase 4 (QR Provisioning completed) marking in STATE.md einleiten.

**Task 3:** Wenn einige Criteria FALSE → Gaps in `03-PHASE-SIGNOFF.md` dokumentieren und Priorisierung für Phase 4 festlegen.
