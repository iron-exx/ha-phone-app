  <action>
    Create `.github/workflows/ios-ci.yml`:
    ```yaml
    name: iOS CI (Simulator build + unit tests)

    on:
      push:
        branches: [main]
        paths: ["ios-app/**"]
      workflow_dispatch: {}

    jobs:
      build-test:
        runs-on: macos-14
        defaults:
          run:
            working-directory: ios-app
        steps:
          - uses: actions/checkout@v4

          - name: Install XcodeGen
            run: brew install xcodegen

          - name: Generate Xcode project
            run: xcodegen generate --spec project.yml

          # Unsigned Simulator build -- requires NO Apple ID, no Developer
          # Program membership, no provisioning profile at all. This is the
          # zero-budget replacement for the previously-planned code-signed
          # device build (see D-11 in 01-CONTEXT.md: the user will not pay
          # for an Apple Developer Program membership in Phase 1).
          - name: Build for iOS Simulator (unsigned)
            run: |
              xcodebuild build \
                -project HAPhoneTestApp.xcodeproj \
                -scheme HAPhoneTestApp \
                -sdk iphonesimulator \
                -destination 'generic/platform=iOS Simulator' \
                CODE_SIGNING_ALLOWED=NO

          - name: Run unit tests on iOS Simulator
            run: |
              xcodebuild test \
                -project HAPhoneTestApp.xcodeproj \
                -scheme HAPhoneTestApp \
                -destination 'platform=iOS Simulator,name=iPhone 16' \
                CODE_SIGNING_ALLOWED=NO

          # NOTE (D-11): This CI pipeline proves ONLY that the app builds and
          # that EnvelopeVerifierTests / PushHandlerTests / DiagnosticsLogTests
          # pass on the iOS Simulator. It explicitly CANNOT prove real VoIP
          # push delivery on a physical device -- PushKit/CallKit VoIP push
          # has zero iOS Simulator support (01-RESEARCH.md Pitfall 4: `xcrun
          # simctl push` does not support the VoIP push type). Real
          # physical-device push verification remains an accepted, open
          # Phase 1 gap (see 01-PHASE-SIGNOFF.md) until the user chooses to
          # pay for an Apple Developer Program membership.
    ```
    This workflow requires zero secrets, zero Apple/App Store Connect accounts, and zero code-signing setup -- Simulator builds do not need a provisioning profile or signing identity at all. The `paths: ["ios-app/**"]` push trigger keeps CI scoped to same-repo pushes to `main` (not arbitrary forked-repo `pull_request` events), and `workflow_dispatch` allows an on-demand manual run.

## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| GitHub Actions macOS runner <-> repo checkout | An ephemeral runner executes code from this repo; a malicious commit/PR could run arbitrary shell inside `xcodebuild`/`brew install` steps |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-05 | Denial of Service | .github/workflows/ios-ci.yml | mitigate | The workflow only triggers on `push` to `branches: [main]` (same-repo, requires write access) plus `workflow_dispatch` (also requires repo write access) -- never on `pull_request` from forks -- preventing an external contributor from triggering unlimited CI runs against this repo's Actions minutes budget |
| T-01-06 | Tampering / Information Disclosure | ios-app/project.yml -> xcodegen generate -> ephemeral .xcodeproj | accept | No secrets, signing material, or credentials of any kind are referenced anywhere in this workflow (verified by the Task 1 acceptance criteria's `grep -c "secrets\."` check returning 0); the generated `.xcodeproj` and unsigned `.app` build product are never uploaded, published, or distributed anywhere -- a compromised runner could only affect its own ephemeral environment, with nothing of value to exfiltrate |
</threat_model>
