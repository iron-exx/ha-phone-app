    Create `ios-app/fastlane/Fastfile`:
    ```ruby
    default_platform(:ios)

    platform :ios do
      desc "Run unit tests (EnvelopeVerifierTests, PushHandlerTests, DiagnosticsLogTests)"
      lane :test do
        run_tests(
          project: "HAPhoneTestApp.xcodeproj",
          scheme: "HAPhoneTestApp",
          devices: ["iPhone 16"]
        )
      end

      desc "Build, sign via match, and upload to TestFlight"
      lane :beta do
        api_key = app_store_connect_api_key(
          key_id: ENV["ASC_KEY_ID"],
          issuer_id: ENV["ASC_ISSUER_ID"],
          key_content: ENV["ASC_API_KEY_CONTENT"],
          is_key_content_base64: true
        )
        match(type: "appstore", api_key: api_key)
        build_app(
          project: "HAPhoneTestApp.xcodeproj",
          scheme: "HAPhoneTestApp",
          export_method: "app-store"
        )
        upload_to_testflight(
          api_key: api_key,
          skip_waiting_for_build_processing: true
        )
      end
    end
    ```
    Create `.github/workflows/ios-ci-testflight.yml`:
    ```yaml
    name: iOS CI + TestFlight

    on:
      push:
        branches: [main]
        paths: ["ios-app/**"]
      workflow_dispatch: {}

    jobs:
      build-test:
        runs-on: macos-14
        defaults:
          run:
            working-directory: ios-app
        steps:
          - uses: actions/checkout@v4

          - name: Install XcodeGen
            run: brew install xcodegen

          - name: Generate Xcode project
            run: xcodegen generate --spec project.yml

          - name: Set up Ruby
            uses: ruby/setup-ruby@v1
            with:
              working-directory: ios-app
              bundler-cache: true

          - name: Run unit tests
            run: bundle exec fastlane test

          - name: Upload to TestFlight
            if: github.event_name == 'workflow_dispatch'
            env:
              MATCH_PASSWORD: ${{ secrets.MATCH_PASSWORD }}
              MATCH_GIT_URL: ${{ secrets.MATCH_GIT_URL }}
              ASC_KEY_ID: ${{ secrets.ASC_KEY_ID }}
              ASC_ISSUER_ID: ${{ secrets.ASC_ISSUER_ID }}
              ASC_API_KEY_CONTENT: ${{ secrets.ASC_API_KEY_CONTENT }}
              APPLE_TEAM_ID: ${{ secrets.APPLE_TEAM_ID }}
            run: bundle exec fastlane beta
    ```
    Note the `paths: ["ios-app/**"]` push trigger only runs the test lane automatically; the `beta` (TestFlight upload) lane only runs on manual `workflow_dispatch`, so every ordinary commit is verified but only an explicit developer action ships a new TestFlight build -- this matches D-10's "CI-round-trip-bound, not instant" iteration expectation without spamming TestFlight on every push.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| GitHub Actions secrets -> workflow run environment | Apple signing/API key material is injected as env vars into an ephemeral macOS runner -- a compromised workflow step or a malicious PR to a forked-repo workflow could exfiltrate it |
| fastlane match private repo -> CI checkout | The encrypted certs repo is a second, separate trust boundary from the app source repo |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-05 | Elevation of Privilege / Information Disclosure | .github/workflows/ios-ci-testflight.yml, fastlane/Matchfile | mitigate | All Apple/match secrets are referenced exclusively via `${{ secrets.* }}` / `ENV[...]`, never hardcoded; the `beta` lane (which needs the secrets) only runs on `workflow_dispatch`, never on arbitrary/forked-repo pushes, limiting the blast radius of a malicious PR; match's certs repo is private and separate from the app source repo, so a leak of one doesn't automatically expose the other |
| T-01-03 | Elevation of Privilege | match password, ASC API key | accept | Single-developer project with a single signing identity for Phase 1 -- rotation/revocation procedure is out of scope until Phase 6's multi-tenant relay, but the developer is instructed (Task 2) to store the match password outside the repo (password manager), not in any committed file |
</threat_model>
