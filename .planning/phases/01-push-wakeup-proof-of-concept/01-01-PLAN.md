## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Test-trigger script -> APNs/FCM | The script sends an unauthenticated-transport (but content-signed) event across the public internet to Apple/Google infrastructure |
| Dev filesystem -> git repository | Signing key material and APNs auth key live on disk and must never cross into the committed history |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Spoofing / Tampering | tools/envelope.py (canonical_bytes, sign_envelope, verify_envelope) | mitigate | Ed25519 signature over canonical, alphabetically-sorted JSON bytes; `verify_envelope` returns False (never raises) on any tamper, enforced by `test_tampered_envelope_fails_verification` |
| T-01-03 | Elevation of Privilege | tools/keys/, tools/.env | mitigate | Both gitignored (`.gitignore` block added in Task 1); `git check-ignore` assertion in acceptance criteria proves the pattern actually matches; private key never printed to stdout by push_trigger.py (only the public key is printed by keygen.py) |
| T-01-04 | Information Disclosure | envelope payload schema itself | accept | Payload carries only a placeholder caller string and non-sensitive routing metadata (event_id/call_id/timestamps) by design (D-06) -- no PII or credentials ever enter the envelope, so leakage via logs/notification history downstream is low-value even if it occurs |
</threat_model>
