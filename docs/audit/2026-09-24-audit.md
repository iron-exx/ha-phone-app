# Audit HA-Phone App + Anlage — 2026-09-24

Sechs unabhängige Prüfungen (Sicherheit Anlage, Sicherheit App, Anruf-Kern, Asterisk-Dialplan, Flutter/UX/Barrierefreiheit, Repos/Doku). Die wichtigsten Funde wurden von Hand nachgeprüft, dann in drei Paketen behoben und im Emulator Ende-zu-Ende getestet.
Ergebnis: **App 1.0.0** (`dc09621`) und **Anlage 0.7.119** (`ff61715`).

## Behoben

### Kritisch
| Fund | Wo | Lösung |
|---|---|---|
| Kein echter Klingelton: nur einmaliger Benachrichtigungston, keine Vibration (per `dumpsys` bestätigt) | App nativ | `RingtonePlayer`: Klingelton in Schleife + Vibration nach Klingelmodus, neuer Kanal „Anrufe“; stoppt auf allen Endwegen. Im Emulator bestätigt (`USAGE_NOTIFICATION_RINGTONE`) |
| Absturzgefahr: Telecom-Coroutines ohne Fehlerbehandlung | App nativ | `SupervisorJob` + Handler, `runCatching` in allen Rückrufen |
| Admin-Login mit Standardpasswort, ohne Bremse, direkt im LAN | Anlage | Sperre nach 5 Fehlversuchen (60 s, verdoppelnd bis 15 min); Pflicht-Passwortwechsel bei „changeme“/„admin“ |

### Hoch
| Fund | Lösung |
|---|---|
| Gesprächsbildschirm schloss sich nach einem vorherigen Anruf sofort („Anruf beendet“) | `lastDisconnected` wird bei jedem neuen Anruf zurückgesetzt, Regressionstest |
| Nach Annehmen bei Sperre lag der Gesprächsbildschirm hinter dem Sperrbildschirm | `showWhenLocked` nur während eines Anrufs (`InCallWindow`) |
| Zweiter Anruf bei gesperrtem, eingeschaltetem Display zeigte nur eine Benachrichtigung | Klingelbildschirm in eigenem Task |
| Hängende Telecom-Anrufe (Anrufer legt vor der Registrierung auf), Auflegen/Annehmen traf den falschen Anruf | Telecom-Registry pro SIP-Anruf |
| Doppeltes Annehmen (Auto + Benachrichtigung) konnte abstürzen | Answer-Guard pro Anruf |
| Anklopf-Benachrichtigung überschrieb die Dienst-Benachrichtigung (gleiche ID 1002) | eigene ID 1003, sicheres `answerWaiting` |
| Konfig-Injektion: Zeilenumbrüche in Namen landeten in Asterisk-Dateien | Validierung aller Freitextfelder + Schutz in `render_conf` |
| Module fehlten: `res_pjsip_caller_id` (Rufnummer eingehender Trunk-Anrufe), `res_pjsip_nat` (`rewrite_contact` wirkungslos), `refer` (Übergabe vom Tischtelefon), `mwi` (Mailbox-Lampe), H.264-fmtp, `func_timeout`, Wartemusik | aktiviert und geladen |
| `*55` schickte den Gesprächspartner nach dem Auflegen zurück in den Dialplan (Voicemail oder alle Telefone) | `Bridge(…,x)`, nur „Up“-Kanäle, kein Konferenz-Peer |
| Feiertage griffen nie (`${YEAR}` existiert nicht) | `${STRFTIME(${EPOCH},,%Y)}` |
| Mehrere Geräte auf einer Nebenstelle: nur eines klingelte | `PJSIP_DIAL_CONTACTS`, `max_contacts=3` (Video-Nebenstellen bewusst 1, wegen Türvorschau) |
| Trunk ohne Anmeldung per Benutzername erreichbar | `identify_by = ip` |
| TalkBack: Tippen auf Tastatur, Status-Pille, Favoriten usw. wirkungslos; „Löschen“ per TalkBack ohne Rückfrage | behoben, Tests |
| Test-Zugangsdaten im APK (`BuildConfig`) | entfernt |

### Mittel / niedrig (Auswahl)
- Uhrzeitsprünge konnten die Neuanmeldung verschieben → `elapsedRealtime`.
- Wake-Lock beim Klingeln und beim Netzwechsel; Mikrofon auch beim Annehmen aus Auto/Headset (FGS `phoneCall|microphone` im Gespräch).
- Absturz nach Backup-Wiederherstellung → `SecurePrefs`, `allowBackup=false`.
- Geister-Klingelbildschirm und 90-s-Klingel-Timeout.
- Veraltete Polls überschrieben neuen Status; Entkoppeln/Neu koppeln ließ alte Daten stehen.
- Kontraste auf WCAG AA angehoben, einheitlich „du“, „Mailbox“/„Sprachnachricht“, toter Code entfernt.
- SRTP-Optionen entfernt (Modul nicht gebaut), TLS-Transport jetzt im Template.

## Offen — braucht eine Entscheidung oder dich
1. **SIP-Passwort von Nebenstelle 13 ändern** (steht im Git-Verlauf, Commits `fff7547`/`e8c09ca`). Das Ändern per API war für Claude blockiert.
2. **Transport-Sicherheit App ↔ Anlage:** API und Kopplung laufen über HTTP, und SIP-TLS prüft das Zertifikat nicht (`verifyServer=false`). Im Heimnetz vertretbar, außerhalb nicht. Lösung: HTTPS + Zertifikat-Fingerprint im QR-Code (Pinning). Größerer Umbau an beiden Seiten.
3. **Kopplungs-Link ohne Rückfrage:** Eine fremde App oder ein Link könnte das Handy an eine andere „Anlage“ koppeln. Lösung: Bestätigungsdialog mit Adresse (klein).
4. **Lizenz:** Die App verlinkt PJSIP (GPLv2), die Lizenz lautet aber „All Rights Reserved“; im HA-Phone-README steht ein MIT-Abzeichen. Vor einer Weitergabe der APK klären.
5. **CI** für `app-flutter` fehlt (nur die alte iOS-App hat einen Workflow).
6. **Release-Signatur:** Die APK ist mit dem Debug-Schlüssel signiert.
7. Das HA-Phone-README beschreibt noch Linphone statt der HA-Phone App.
